# 修复 6 项错误 + 2 项优化 计划

## 概要

基于对 `game.html`、`js/main.js`、`js/gamesystems.js`、`js/achievements.js`、`js/data.js`、`css/style.css` 的完整探索，定位了全部 8 项问题的根因。本计划按问题逐项给出精确到文件/行号/函数的修复方案。

用户已确认的决策：
- 问题3（物品引用）：导出按钮报错 + 导出文本贴回输入栏显示纯文本，**两种都修**
- 问题2（选项兜底）：AI 漏 `[choice]` 时**自动重试请求 AI 补选项**，失败再回退中性选项

## 一、错误修复

### 错误1：收集物资后未弹出侧边弹窗，物资未收容到背包

**根因（三层）**：
1. **标签解析容错不足**：[main.js ptg() L2426-2438](file:///workspace/js/main.js#L2426)。`tg.startsWith('物品:+')` 只匹配英文冒号紧跟 `+`。AI 输出 `[物品：+罐头]`（中文冒号）、`[物品: +罐头]`（冒号后空格）等变体时解析失败 → 无弹窗、不入包。
2. **入包去重逻辑错误**：[main.js mds() L2249-2255](file:///workspace/js/main.js#L2249)。`!s.inv.includes(v)` 严格字符串匹配，背包已有"罐头"时 AI 再给"罐头"被**静默丢弃**；且不走 `invAdd()`，数量不合并（"罐头"与"罐头x2"碎片化）。
3. **系统掉落路径无弹窗、不合并**：[gamesystems.js L223（战斗掉落）/L323（合成）/L522（随机事件）/L565（季节事件）](file:///workspace/js/gamesystems.js#L223) 全部裸 `s.inv.push`，无 `snotify('add')`。

**修复**：
- **A. ptg 标签归一化**（main.js L2426 回调开头）：`tg = tg.replace(/：/g, ':').replace(/:(\s+)/g, ':')` 后再做所有 startsWith 匹配（一处归一化，全部标签受益：物品/装备/血量/线索等中文冒号变体全部兼容）。
- **B. mds 的 aiList 入包改造**（main.js L2249-2255）：
  ```js
  if (ch.aiList && Array.isArray(ch.aiList)) {
      const s = gst();
      const picked = [];
      ch.aiList.slice(0, 8).forEach(v => {
          if (!v) return;
          const base = parseItemQty(v).base;
          const exists = s.inv.some(x => parseItemQty(x).base === base);
          const r = invAdd(v, 1);          // base 名去重 + 数量合并
          if (!exists) picked.push(v);     // 只有新物品才算"拾取"音效
          else playSfx('pickup');
      });
      if (ch.aiList.length > 8) snotify('status', '物资限制', '单次收集已上限8种，多余物品未拾取');
      upui();
  }
  ```
  删除 L2247 的死代码 `if (ch.ai)`（`ch.ai` 从未被赋值）。
- **C. 统一系统掉落入包**：main.js 中将 `window.invAdd = invAdd;` 挂全局（放在 `invAdd` 定义后，参考现有 `window.gst = gst` 等模式）。gamesystems.js 4 处 `s.inv.push(...)` 改为：
  ```js
  (window.invAdd ? window.invAdd(item, 1) : s.inv.push(item));
  snotify('add', '战利品', item);  // L223 战斗掉落
  ```
  其余 3 处分别用 label '合成' / '事件物资' / '季节物资'，紧跟已有 tst/playSfx。
- **D. 解析失败时的可见反馈**：ptg 归一化后仍无法识别的 `[物品:...]` 变体（如 `[获得物品:罐头]`）在 ptg 内识别 `tg.startsWith('获得物品:')` / `tg.startsWith('物品获得:')` 两个常见变体一并映射到 aiList。

### 错误2：建议选项时有时无、与上文不符

**根因**：
- [main.js L3408-3413](file:///workspace/js/main.js#L3408)：AI 未输出 `[choice]` 时直接追加 `generateDefaultChoices()`（L3053-3064，生成"寻找食物/找水/休息"等与剧情无关的固定选项），且**拼回 `full` 写入 hist**（L3412-3414），污染历史。
- [main.js L3448-3458](file:///workspace/js/main.js#L3448)：网络重试按钮绑定用了错误选择器 `.vn-choice-bubble` / `.vn-choice-item`（实际类名是 `.vn-choice-container` / `.vn-choice`，见 L2811/L2824），重试按钮永远绑不上事件。
- [safeSplitChoices L3113-3115](file:///workspace/js/main.js#L3113)：按空格/逗号切分可能把一句话误切多份。

**修复（按用户选择：自动重试 AI 补选项）**：
- **A. hin() 中新增补选项重试**（替换 L3408-3413 的直接兜底）：
  ```js
  if (!isIdle && !/\[choice\]/i.test(full)) {
      let opts = null;
      try {
          // 轻量补选项请求：以刚输出的剧情为上下文，要求只回 [choice] 区块
          const retry = await requestChoiceTopUp(full);
          if (retry && retry.length) opts = retry;
      } catch(_) {}
      if (!opts) opts = generateNeutralChoices(); // 中性兜底（见 B）
      try { apb({ ty: 'choice', opts }, 0); } catch(_) {}
      // 注意：不再把兜底 [choice] 拼回 full / hist
  }
  ```
  `requestChoiceTopUp(storyText)`：调用现有 API 发送通道（复用 hin 内的 fetch 逻辑抽出的底层函数），messages = 最近 2 条 hist + 一条 user 指令：`"以下是刚才的剧情正文。请严格按格式输出 3-4 个承接剧情的选项，格式：[choice]选项1|选项2|选项3[/choice]，不要输出其他任何内容。\n\n" + storyText.slice(-2000)`；解析返回中的 `[choice]...[/choice]` → safeSplitChoices。设置 8s 超时 + 单次重试上限（防循环）。
- **B. generateNeutralChoices() 替换 generateDefaultChoices 作为最终兜底**：只含不涉及剧情方向的选项 `['观察周围环境', '检查随身装备', '原地警戒片刻']`，绝不生成"寻找食物/找水"这类可能与剧情冲突的内容。原 `generateDefaultChoices` 保留但不再用于此路径（挂机模式仍可用）。
- **C. 修复重试按钮选择器**（L3450-3458）：`.vn-choice-bubble` → `.vn-choice-container:last-of-type`，`'.vn-choice-item'` → `'.vn-choice'`。
- **D. safeSplitChoices 收紧**（L3113-3115）：无 `|` 分隔时只在**换行**处切分（去掉按空格/逗号切分的分支）。

### 错误3：物品引用到输入栏未正常显示（导出角色设定按钮）

**根因**：
- [exportCharacter() L6948-7010](file:///workspace/js/main.js#L6948)：L6984 `初始物品：' + (c.it || '无')` 纯文本拼接，无 `{{}}` 引用标记 → 贴回输入栏后 `abold` 的 `{{}}` 正则不匹配，渲染不出 item-ref 胶囊。
- 按钮报错：导出流程无 try/catch，`playSfx('success')` / `URL.createObjectURL` 任一环节数据异常（如 gch() 返回带异常 getter 的对象）即抛错且无提示。
- 输入栏为 contentEditable 模式时，粘贴含 `{{物品名}}` 的纯文本不会转成 chip。

**修复**：
- **A. exportCharacter 加固**：整个函数体包 try/catch，catch 中 `tst('导出失败：' + e.message)`；物品行改为引用格式：
  ```js
  const itemsRef = (c.it || '无').split(/[,，、]/).map(x => x.trim()).filter(Boolean)
      .map(x => '{{' + x + '}}').join('、') || '无';
  lines.push('初始物品：' + itemsRef);
  ```
- **B. 输入栏 `{{}}` 实时转 chip**：在输入栏初始化处（main.js 搜索 `inputText` 的 contentEditable 初始化段）加 `input` + `paste` 监听：检测到 `{{...}}` 文本且 `getItemInfo(name)` 存在时，将其替换为 `insertItemChip` 同款 `.item-chip` 节点（复用现有 chip 构造逻辑，抽成 `makeItemChipNode(name)` 供两处使用）。TEXTAREA 模式保持字面 `{{}}`（发送后 AI 回复侧已正常渲染，不动）。
- **C. abold 物品匹配扩展**（[main.js L1548-1563](file:///workspace/js/main.js#L1548)）：names 收集时同时遍历 `s.equip` 的值（装备后移出背包的物品名仍可加粗），修复"装备后日志里物品名不再加粗"。

### 错误4：属性数值变化速度过快，低数值时无感知

**根因**：
- [upui() L2083-2099](file:///workspace/js/main.js#L2083)：顶部数字直接 `textContent = 新值`，无过渡，变化一闪而过。
- 面板进度条：`_setInnerHTMLIfChanged`（L2009-2015）整体 `innerHTML` 重建，新 `<div class="sp-bar-fg">` 以目标 width 直接创建，CSS 的 `transition: width 0.5s`（[style.css L2272-2276](file:///workspace/css/style.css#L2272)）永不触发。

**修复**：
- **A. 顶部数字 tween**：新增 `tweenNum(el, from, to, ms)`：requestAnimationFrame + easeOutCubic，约 450ms 完成插值；upui 中每个 `st*` 数字变化时调用（保留 `el._v` 缓存判断"是否变化"）。
- **B. 变化浮动指示**：新增 `flashDelta(el, delta)`：在数字元素旁生成 `+N` / `-N` 小浮层（CSS 类 `.st-delta`，上浮渐隐 900ms 动画），下跌用红色、上涨用绿色；delta 由 `新值 - el._v` 计算。低数值时用户对变化无感 → 浮层直接可视。
- **C. 面板进度条两帧法触发过渡**：`_setInnerHTMLIfChanged` 替换 innerHTML 后（仅 sideProps 场景），新增后续步骤：
  1. 渲染前把旧的各 `sp-bar-fg` 宽度按行序存入数组 `oldWidths`；
  2. 替换后新元素先 `style.width = oldWidths[i]`（无过渡）；
  3. `requestAnimationFrame` 下一帧设为目标宽度 → transition 生效。
  实现上在 upui 的 sideProps 分支：替换前 `const olds = [...$('sideProps').querySelectorAll('.sp-bar-fg')].map(e => e.style.width)`，替换后循环回填旧宽，再 rAF 设置新宽（新宽从 html 字符串中正则提取 `width:(\d+\.?\d*)%`）。
- **D. CSS**：style.css 新增 `.st-delta` 浮层样式（绝对定位、pointer-events:none、上浮动画 keyframes `stDeltaFade`）。

### 错误5：触发了死亡结局，但未正常运行

**根因**（[gamesystems.js triggerDeathEnding L1460-1479 / generateDeathEnding L1480-1579](file:///workspace/js/gamesystems.js#L1460)）：
1. `playSfx('death')` 无声：gamesystems.js L1368 覆盖的 `window.playSfx`，其 `sfxExt`（L1348-1365）/`defaults`（L1389-1404）无 `'death'` 条目（audio.js L96/L190 有但永不被调用）。
2. 2 秒 `setTimeout` 竞态：期间用户可继续操作，且 `s` 引用可能已过期。
3. `#deathNewChar`：L1532 `$('charModal').style.display` 无 null 保护，charModal 缺失时 onclick 抛错静默失败。
4. `#deathLoadSave`：无存档时弹窗已 `remove()`（L1537 先执行），只 `tst()` 提示，用户以为按钮坏了。

**修复**：
- **A.** sfxExt map 补 `'death': { freq/tone 配置，参照 audio.js L96 的 death 映射转成 WebAudio 参数 }`（或 defaults 补 `'death': [低频下行音效参数]`）。
- **B.** `triggerDeathEnding`：2 秒延迟改为立即调用 `generateDeathEnding`（死亡时刻锁定状态更可靠）；同时置 `window._deathLock = true` 防重入，`generateDeathEnding` 弹窗创建后清除。
- **C.** `#deathNewChar` onclick 包 try/catch + `const cm = $('charModal'); if (cm) cm.style.display = 'flex'; else tst('角色创建面板未就绪');`
- **D.** `#deathLoadSave`：先扫描存档，无存档时 `tst('没有可用的存档')` 且**不 remove 弹窗**（return 在 remove 之前）；有存档才继续 remove + 恢复。
- **E.** 死亡期间输入拦截：`hin()` 入口（main.js 约 L3120 起）最前面加 `if (gst().deathShown && !cfg().debug) { tst('角色已死亡，请选择结局操作'); return; }`，防止弹窗期间继续推进剧情导致状态错乱。

### 错误6：成就系统超前解锁未获得的成就

**根因**：
- **致命：无限递归栈溢出**。[main.js L7339](file:///workspace/js/main.js#L7339) `window._checkAchievements = () => checkAchievements();` 覆盖了 gamesystems.js L1611 的真实实现，而 main.js L3535 的转发器又回调 `window._checkAchievements` → 死循环。装备/卸下（main.js L4324/4344/4423/4437 调用本地 `checkAchievements()`）全部栈溢出被吞，成就判定在装备场景完全失效。
- **条件过宽松**（[achievements.js](file:///workspace/js/achievements.js#L42)）：
  - `frost_resistant`（L42）：`s.snowSurvived` truthy 即解锁（一次暴雪就成）。
  - `vehicle_master`（L76）：`s.vehicle && s.vehicle !== '无'` 任意载具即解锁。
  - `social_butterfly`（L66）/`diplomat`（L67）：只数 `npcRel` 键数量，关系破裂的也算。
  - `weapon_enthusiast`（L53）：正则 `/枪|刀|斧|.../` 不锚定，"弹弓/刀鞘/枪油"误判。
  - `armor_collector`（L54）：正则匹配"套/服/甲"等，"避孕套/校服/马甲"误判。
  - `eagle_eye`（L99）：发现 1 个即解锁，门槛与 desc 不符时偏高偏低。
- **过严格**：`collector/hoarder/museum`（L48-50）只数当前 `s.inv`，丢弃后计数下降，与"收集过 N 种"语义不符。

**修复**：
- **A.** 删除 main.js L7339 的 `window._checkAchievements = () => checkAchievements();` 覆盖行（保留 gamesystems.js L1611 的赋值为唯一真实实现；main.js L3535 转发器因此恢复正常转发）。参照同文件 L7337-7338 注释中已为 `_addLogEntry` 避免的同一反模式。
- **B.** achievements.js 条件修正（每项对齐 desc 语义）：
  - `frost_resistant`：`(s.snowSurvived || 0) >= 2`
  - `vehicle_master`：`(s.vehicleCount || 0) >= 3`（若 desc 为"集齐3种载具"；执行时先读该成就 desc 文本，按 desc 数字对齐）
  - `social_butterfly` / `diplomat`：`Object.values(rels).filter(r => r.trust >= 20).length >= 5/10`
  - `weapon_enthusiast` / `armor_collector`：优先用 `getItemInfo(name)` 的类型/subCategory 字段判断（存在 ITEM 数据库类型时）；无类型数据时正则改为 `(?:枪|刀|斧|弓|弩|剑|锤|棍|棒|矛|炮|刃)$`（结尾锚定，排除"枪油/刀鞘"）
  - `collector/hoarder/museum`：改用累计计数 `s.collectedTypesCount`（新增字段：mds 的 invAdd 成功新增 base 时 `s.collectedTypesCount = (s.collectedTypesCount||0)+1`，仅当该 base 首次出现）；三成就阈值对齐 desc
- **C.** 关键事件即时检查：mds 中物品入包成功后、gamesystems.js 战斗胜利击杀后（L223 附近）、合成成功后（L323 附近）各追加 `(window._checkAchievements || function(){})()` 调用，减少 15 秒定时器延迟。

## 二、优化

### 优化1：建议选项输出格式

- **cbe() 的 choice 分支**（[main.js L2821-2881](file:///workspace/js/main.js#L2821)）：按钮内容加序号徽标 `①②③④`（按 opts 索引）+ 前缀图标 `▸`，长选项自动两行省略。
- **style.css**：`.vn-choice` 增加 hover 位移 + 边框变色 + 序号徽标 `.vn-choice-num`（圆形小徽章，手绘风格 border-radius 不规则值，与现有 UI 语言一致）；激活按下 `transform: translateY(1px)`。
- 纯 CSS + 渲染字符串小改，不动事件逻辑。

### 优化2：系统日志物品完全适配

**现状**：`addLogEntry` 全部纯文本拼接（main.js L4323/4343/4422/4436、gamesystems.js L325/1474 等），渲染只靠 abold 对"当前 inv 中同名物品"模糊加粗——物品离包即失效，且永远拿不到 `.item-ref` 胶囊样式与 tooltip。

**修复**：
- **A.** main.js 新增 `iref(name)` 工具：`name ? '{{' + name + '}}' : ''`，供拼接日志时包裹物品名。
- **B.** 各 `addLogEntry` 调用点物品名改包裹：`'装备了 ' + iref(item.name) + ...`、`'卸下了 ' + iref(itemName)`、`'成功合成：' + iref(recipe.result)`、`'AI合成：' + iref(ch.craftResult)`、战斗掉落新增日志 `'获得战利品：' + iref(loot)`。
- **C.** openLogViewer 渲染（gamesystems.js L926）已走 `abold(displayText)` → `{{}}` 自动渲染为 `.item-ref` 胶囊 + `data-item-info` tooltip，无需改渲染器。
- **D.** `attachLogItemPreview`（L836-870）已有 `.auto-bold` tooltip 绑定，item-ref 节点同样会被 `buildItemTooltipHTML` 覆盖，验证无冲突即可。
