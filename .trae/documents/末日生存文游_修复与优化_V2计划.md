# 末日生存文游 - 修复与优化 V2 实施计划

## 一、代码库调研结论

### 项目结构
- 核心架构：纯原生 HTML + CSS + JavaScript（IIFE 模块化封装），无构建工具
- 入口页面：`index.html`（主菜单/配置）→ `game.html`（游戏主界面）
- 脚本加载顺序（game.html）：`audio.js` → `data.js` → `items_data.js` → `npc_data.js` → `events.js` → `achievements.js` → `gamesystems.js` → `main.js`
- 存储：全部使用 `localStorage`，键前缀 `vn_` / `dz_`

### 核心模块与职责
| 文件 | 职责 | 关键全局函数 |
|------|------|-------------|
| `js/audio.js` | 音效/BGM/Toast/对话框/点击音 | `playSfx`, `bgmPlay*`, `tst`, `sfxEnabled` |
| `js/data.js` | 纯数据常量（物品预设、DPROMPT、沙盒配置 DSBX、职业预设 JOB_PRESETS） | `window.DPROMPT`, `window.ITEM_PRESETS` |
| `js/events.js` | 随机突发事件定义 RANDOM_EVENTS + EVENT_TRIGGERS | `window.RANDOM_EVENTS` |
| `js/achievements.js` | 成就定义数组 + 判定条件函数 | `window.ACHIEVEMENTS` |
| `js/gamesystems.js` | 战斗/合成/事件调度/日志/死亡结局/成就检查/导入导出 | `triggerDeathEnding`, `triggerRandomEvent`, `invAdd`(部分), `addLogEntry` |
| `js/main.js` | 核心业务：时钟系统/状态衰减/物品入包/输入栏/UI 渲染/AI 调用 hin()/snotify() | `gst`, `gch`, `gclk`, `sst`, `upui`, `hin`, `invAdd`, `snotify`, `startClock` |

### 上一轮修复遗留的结构性问题
1. **脚本加载顺序**：`gamesystems.js` 先于 `main.js` 加载，已通过箭头包装动态解析修复（见 gamesystems.js L47-117）
2. **函数引用碎片化**：main.js 顶部 IIFE 内部用 `const _origXxx = window.xxx` 预存快照，`snotify` 定义在 L1661 附近形成自引用，存在递归/循环风险
3. **时钟系统**：main.js L499 `clockTimer = null` + `setInterval` 驱动 `decayStatus`，属于"自动流失"模式，需全面改造
4. **AI 选项解析**：`cbe()` 函数（choice bubble element）渲染选项，`hin()` 中处理 `[choice]...[/choice]` 标签

## 二、修复项（6 类）

### 修复 1：物品引用错误插入「导出角色设定」按钮
**根因分析**：
- 从截图看，`exportCharacter` 输出文本时，物品名被 `{{物品名}}` 包裹；但用户将这段文本复制后粘贴时，粘贴事件处理逻辑定位错误，将 chip 插入到了 `#btnExport`（导出按钮）的 textContent 而非 `#inputText`。
- 可能涉及：`exportCharacter` 输出流、剪贴板粘贴监听、`insertItemChip` 的 DOM 选择器。

**修改文件**：`js/main.js`
1. **定位并修复粘贴监听目标**：
   - 搜索 `addEventListener('paste',` 或 `onpaste`，确保只绑定到 `#inputText`（contentEditable / textarea）。
   - 如果是全局 `document` 级 paste 监听，加条件：`e.target.closest('#inputText')` 才执行转换。
2. **修复导出按钮内容污染**：
   - `exportCharacter` 弹窗的 DOM：检查 `#btnExport` 或"导出角色设定"按钮的 `textContent` 是否被追加了文本；确保 `exportCharacter` 只写入到弹出的 `<textarea>` 或剪贴板，不改动按钮本身。
   - 若存在"将导出结果插入到某个元素"的代码，确认目标元素 ID 不是按钮。
3. **加固 insertItemChip()**：
   - 首行加空值/目标校验：`if (!el || !el.isContentEditable && el.tagName !== 'TEXTAREA') return;`
   - 防止 Selection Range 在另一个元素上时意外写入别处。

### 修复 4：侧边提示气泡（snotify）不正常
**根因分析**：

- notifyQueue / notifyBusy 的 `processNotifyQueue()` 可能在 `_replayingHistory=true` 时被锁死不再解锁。

**修改文件**：`js/main.js`

2. **解锁死锁**：`processNotifyQueue()` 结束后无论成功失败都 `notifyBusy = false`；再加 `setTimeout` 兜底每 500ms 强制 check 一次队列。
3. **移除或缩短冷却**：`_notifyCooldownByType['add']` 2s 有点长且 `noValueSig` 匹配会误杀"不同物品同分类"的通知，改成 `valueSig`（带具体物品名）维度冷却即可。

### 修复 5：AI 生成打断 BGM + 状态<0 不触发死亡 + 开局随机状态低于阈值
**修改文件**：`js/audio.js`, `js/main.js`, `js/gamesystems.js`

#### 5.1 AI 生成打断 BGM
- **根因**：`ensureAudio()` 在每次请求时被调用，`AudioContext.resume()` 或 新建 `Audio` 实例导致 BGM 的 `audio.currentTime` 被重置/暂停。
- **修复**：
  - `hin()` 中去掉不必要的 `ensureAudio()` 调用（仅在首次交互后调用一次即可）。
  - 搜索 `audio.js` 中任何 `BGM.audio.pause()` 或 `currentTime = 0`，确认不是在非 bgm 切换路径触发。
  - bgmAutoSwitch / bgmPlayCategory 加「同一分类 + 同一曲当前正在播放时直接 return，不做任何 src 重设」。

#### 5.2 状态<0 不触发死亡
- **根因**：mds() 中死亡判定条件只看 `s.hp <=0`，其他属性（饥饿/口渴/疲劳/体温/精神）低于 0 时只扣 HP，扣到 0 的触发路径可能在 15s 定时器而非即时。
- **修复**：
  - `decayStatus()` 末尾 + `mds()`（状态 UI 更新）中各加一次统一死亡检测：
    ```
    function _checkDeathNow() {
      const s = gst(); if (!s || s.deathShown || window._deathLock) return;
      // 任何关键属性触底 → hp 直接归 0
      if (s.hunger <= 0 || s.thirst <= 0 || s.bodyTemp <= 32 || s.hp <= 0 || (s.infection || 0) >= 100) {
        s.hp = 0;
        triggerDeathEnding(s);
      }
    }
    ```
  - 每次玩家行动推进后立即调用 `_checkDeathNow()`（而非等待 15s 轮询）。

#### 5.3 开局玩家随机状态不得低于正常阈值
- **根因**：`DSTA` 默认值 hunger:70/thirst:70 看起来正常，但 `aiInitStats()` 或角色创建页面的"随机"按钮会把值随机化到 0-100，可能出现 <30 的情况。
- **修复**：
  - `aiInitStats()` / 随机状态按钮：限制最小值：`hunger ∈ [45, 85]`、`thirst ∈ [45, 85]`、`fatigue ∈ [5, 35]`、`bodyTemp ∈ [36.2, 37.2]`、`hp ∈ [85, 100]`、`spirit ∈ [70, 95]`。
  - 角色确认创建时再次 clamp 校验。

### 修复 6：重新规划突发事件的作用和相关功能
**当前问题**：`events.js` 中 RANDOM_EVENTS 基本都是 snotify 弹窗，没有实质效果（只警告"水源清洁"却不 +thirst，只说"陷阱"却不 -hp）。

**修改文件**：`js/events.js`, `js/gamesystems.js`, `js/main.js`
1. **事件分类重新定义**：
   - **立即效果类（Effect）**：获得/失去物品、HP/thirst/hunger/fatigue ±N、解锁地图、获得线索、关系变化；事件 execute() 必须直接调用 `invAdd` / `gst().hp -= X` / `snotify` 三件套。
   - **AI 叙事钩子类（Hook）**：只往系统提示区插一条"背景事件"，由 AI 在下一轮叙事中承接（通过 systemPromptExtra 注入）。
   - **玩家二选一事件（Choice）**：弹窗给玩家 A/B 选项，选后执行不同效果。
2. **触发渠道统一**：
   - 不再使用 `setInterval` 定时检查（配合时间系统重构删除）。
   - 改为**玩家行动推进时按概率抽取**：每次 `advTime(+Xh)` 后，以 `eventFreq`（沙盒 cat3）为权重，从 RANDOM_EVENTS 中挑 `minDay<=day<=maxDay` 且 `trigger()===true` 的事件，按 `weight` 加权抽取 0~1 条。
3. **季节/天气事件并入**：暴风雪天气的冻伤、暴雨的疲劳、晴天的精神恢复，作为"被动持续效果"归入 decayStatus（已部分存在），不用 random event。

### 优化 1：重构时间系统 → 随玩家行动推进 + 昼夜跟随现实流速
**修改文件**：`js/main.js`, `js/gamesystems.js`, `js/data.js`（DSBX）, `game.html`（相关 UI 字段）

#### 1.1 删除内置计时器
- 删除 `startClock()` 里的 `setInterval(tickClock, 1000)`；删除 `clockTimer` 变量。
- 删除 `decayStatus` 的"按现实秒 elapsedSec 换算 gameHours"调用链。

#### 1.2 引入 `advTime(gameHours, reason)` 作为统一时间推进入口
- 玩家行动（发送输入）后调用 `advTime(N, '玩家行动')`，其中 N 由 AI 返回的 `[时间:+Xh]` 标签决定，若 AI 未写则默认 +1h。
- 挂机模式（idleOn）：按 idleInt 秒间隔（但也是基于"setTimeout 一次性"而非定时器循环，调用一次就 advTime(+0.5h)）。
- `advTime(hours)` 内部：
  1. `gclk().elapsedSec += hours * 3600`
  2. `day = floor(elapsedSec/86400) + 1`
  3. `decayStatus(hours)` 调用（饥渴疲劳 HP 等属性）
  4. **昼夜跟随现实时间**：
     - DSBX 中 "昼夜流速" 字段含义改为：`dayLenSec` 保留但含义切换为「现实秒/游戏小时」或直接提供「跟随系统时间」的 toggle。
     - 具体做法：新增 `DSBX.cat1.fields.realTimeSync: {label:'昼夜跟随现实时间', type:'toggle', val:true}`；开启时忽略 dayLenSec，游戏时钟 = 本地设备的时钟（dayPhase 随本地小时，季节随本地月份）；关闭时用 `dayLenSec` 固定缩放（但仍由玩家行动触发 tick，而非自动流逝）。
  5. `updClockUI()` 刷新 UI
  6. `_checkDeathNow()` 立即检测
  7. `checkRandomEvent()` 按概率抽事件
  8. `_checkAchievements()` 成就检查

#### 1.3 沙盒设置整改
- 删除 `DSBX.cat1.fields.dayLenSec` 的"自动流逝"说明文案；改为「跟随系统时间开关」+「手动推进缩放（仅离线模式可用）」。
- `game.html` 中沙盒面板渲染逻辑（`renderSbxCat` 之类）同步更新。

### 优化 5：便签线索完成后自动删除
**修改文件**：`js/main.js`（s.clues 维护处 + addLogEntry 线索完成判定）, `js/gamesystems.js`

- 思路：当玩家行动叙事中出现「线索 xxx 已查清 / 破解了 xxx 的线索 / 查明了 xxx」等表达，AI 或本地正则识别到后，自动从 `s.clues` 中移除对应条目。
- 实现步骤：
  1. `hin()` 处理完 AI 回复的 `full` 后，运行 `_autoCheckClueCompletion(full)`：
     - 正则：`/(?:查清|破解|查明|解开|完成|结束|搞定|确认|弄清楚|解决|不再需要|无关紧要)[了过]?[，。、\s]*线索?[《「""“”]?([^《」""”》，。；：\s]{2,20})/`
     - 以及反向：`线索?[《「""“”]?([^》」""”，。；：\s]{2,20})[《」""”》]?.*(?:已完成|已解决|不再追踪|告一段落|查清|破解|结束)`
  2. 匹配成功后：
     ```
     s.clues = s.clues.filter(c => !c.includes(matchName) && !matchName.includes(c.text || c));
     sst(s); upui();
     snotify('clue', '线索完成', matchName + '（自动移除）');
     addLogEntry('system', '线索已完成，自动移除：' + matchName);
     ```
  3. 提供"撤销移除"的 undo 操作（s.undo 栈里 push 一个 clue remove 记录）。

- **现状假设**：当前地图是纯文本或静态 grid。
- 优化方案：
  1. 地点节点改为可点击：每个 `map-node` 添加 `click` → 弹出「这是 xxx。是否立即前往？」确认框；确认后在输入栏自动填入「前往 xxx」并发送（省玩家打字）。
  2. 已解锁 vs 未解锁：未解锁地点用灰色 + ❓占位符，hover 时显示解锁条件（"在剧情中发现后解锁"）。
  3. 当前位置高亮：玩家 `gst().location` 匹配的节点加脉冲动画（CSS `@keyframes mapPulse`）。
  4. 视觉优化：给地图容器加手绘风格背景 + SVG 道路连线（如果目前是纯列表则升级为 force-layout 简易网格）。
  5. 点击节点时 `playSfx('map')`（tone 音，新增一个 SFX 类型）。

### 优化 7：优化网页响应速度
**修改文件**：`js/main.js`, `js/audio.js`, `js/gamesystems.js`, `css/style.css`

1. **减少 reflow**：`upui()` 中对 `.st-hp-val` 等数值更新使用 `documentFragment` 批量改 DOM；不要逐条元素 `textContent =`。
2. **`requestAnimationFrame` 合并 UI 更新**：`upui()` 调用节流（L409~ 附近 `let upuiT`，同一帧多次调用只跑最后一次 + 最多 16ms 延迟）。
3. **懒加载成就/背包 grid**：条目 >50 时，使用 IntersectionObserver 分页渲染或虚拟滚动。
4. **BGM 预加载更节制**：不是所有分类第一首都立刻预载，而是进游戏先 preload title + camp 两首，其他分类按"即将切换"时才 preload。
5. **localStorage 读写节流**：`sv()` 内部已有 setTimeout 异步 backup；再给主写加 16ms debounce（同一 key 连续写合并为最后一次）。
6. **CSS**：`will-change: transform` 给 notify / choice bubble 动画元素；`contain: layout paint` 给侧边栏和日志区。

### 优化 8：减少不必要的 token 费用
**修改文件**：`js/main.js`（hin() 发送 messages 构建）, `js/data.js`（DPROMPT）

1. **裁剪上下文**：`hist` 不是全部发送，而是「系统提示 + 最近 N 条对话 + 压缩摘要 + 最近 1 条关键系统状态更新」。N 默认 14（双方 7 轮），可调 cfg。
2. **生成对话摘要**：超过 ctx 阈值时，用单次调用总结前 N 条（max_tokens 512，低 temperature），替换掉旧的对话，节省后续每轮 token。
3. **max_tokens 收缩**：默认 DPROMPT 里剧情要求每轮 600~1000 字就够，maxT 默认 2048 可以降到 1200；挂机模式进一步降到 800。
4. **system prompt 裁剪**：DPROMPT 删除冗余重复的"规则 x.x 标题"；合并同类；沙盒参数只传变化项而非全量。
5. **选项补选项（补 3-4 choice）温度 0.7，max_tokens 降到 128**（本来就只需要选项，不需要长文本）。
6. **空闲挂机（idleOn）批量**：idleInt 60s 太长没用，改成 180s 或玩家手动触发，避免 AI 无意义连续生成。

### 优化 9：优化系统 Prompt（不过度引导、限制选项字数 ≤ 两行气泡）
**修改文件**：`js/data.js`（DPROMPT）

1. **「不要过度引导」**：删除或弱化 DPROMPT 中「建议玩家去做 xxx」「玩家应该」这类措辞；改写成「输出剧情后提供 3-4 个可执行选项，但不要替玩家做决定」。
2. **选项字数限制写入 Prompt 硬性规范**：
   - 「每个选项字数 **不超过 18 个汉字**（不含标点），超出部分会被前端强制截断，请严格控制。」
   - 「选项必须为具体动作短句，不含任何标签、符号、序号、项目符号。」
3. **AI 不要做"伪上帝评论"**：新增"禁止输出场外点评、禁止事后诸葛分析；只写剧情 + 选项"。
4. **降低 AI "教学口吻"**：明确"不输出"玩家""宿主"等称谓（已在 DPROMPT 顶部），再强化一次「不用称呼玩家，直接叙述」。
5. **标签收敛**：允许 AI 使用的标签只有 `[时间:+Xh]`、`[choice]...[/choice]`、`[状态:xxx±N]` 三种，其余标签禁止输出。

## 四、提议项：构建 AI 调用框架（模板/输出协议系统）
**目标**：让 AI 严格按模块协议输出，从源头降低"调用错误 / 选项出标签 / 物品没收容"等细节问题。

**修改文件**：`js/main.js`（新增 `FRAMEWORK_PROTOCOL` + `_validateAiOutput` + `_repairAiOutput` + `_buildFrameworkContext`）, `js/data.js`（可合并入 DPROMPT 或新增单独段）

### 4.1 框架协议（注入到 system prompt 末尾 + 本地校验）
定义「AI 输出契约」，以下为实际注入 Prompt 中的文本：
```
【★ 输出协议 Framework Protocol v1.0 — 强制遵守】
每轮你输出的内容必须严格符合下方机器可读结构，任何违反结构的输出将被自动修复或重试：

1. BLOCK_1 剧情正文（纯文本，必填）：
   - 角色视角叙事，纯小说式写法；
   - 内联规则：物品名、地名人名用 【】 或 {{}} 包裹；
   - 可内嵌机器标签（行尾或独立段落）：
       · [时间:+3h]       — 表示剧情推进了 3 小时（数字可改，必填/选填任选，但建议写）
       · [状态:血量-10]    — 格式 [状态:属性±数值]，多个时用空格分隔
       · [物品:+绷带x2]   — 格式 [物品:±物品名x数量]，多物品用 ；分隔
       · [线索:+东区军火库地图] — 格式 [线索:±线索名]
       · [地图:+港口]     — 格式 [地图:±地点名]
       · [死亡]           — 单标签，仅当角色确认死亡时输出一次
   所有内嵌标签必须写在 BLOCK_1 末尾，不要穿插在叙事段落中间。

2. BLOCK_2 选项（[choice] 包裹，必填）：
   - 紧接 BLOCK_1；格式固定：
       [choice]
       选项1文本
       选项2文本
       选项3文本
       [/choice]
   - 严格要求：选项数 2-4 个，单个选项 4-18 汉字，纯文本，无任何序号/前缀/符号/标签。
   - 禁止：[choice] 中间出现 【】、{{}}、*、-、数字 1. 等开头。

【校验失败自动修复机制说明】：
- 如果你没有写 [choice] 或选项内容不合规，前端会自动调用你再生成一次选项。
- 如果你忘记输出 [物品:] 但剧情中明确提到了获得/失去物品，前端会从剧情文本里自动提取并强制执行。
- 请你尽量一次写对，减少自动修复次数 = 降低 token 消耗 = 玩家体验更流畅。
```

### 4.2 本地校验 + 修复管线 `_validateAiOutput(full)`
- **阶段 1 提取**：
  1. `choiceMatch = full.match(/\[choice\]([\s\S]*?)\[\/choice\]/i)`
  2. `tagMatches = [...full.matchAll(/\[(时间|状态|物品|线索|地图):([^\]]+)\]/gi)]`
  3. `deathTag = /\[死亡\]/.test(full)`
- **阶段 2 校验**：
  - 选项数 2-4 个？单个 ≤18 字？无标签前缀？
  - [物品] 标签中的物品名是否合法？数量是数字？
- **阶段 3 自动执行**（不等 AI 下次确认）：
  - 解析 `[状态:]` → 直接更新 `gst()` 属性并调用 `sst()`/`upui()`
  - 解析 `[物品:]` → 调用 `invAdd` / `invRemove`（**从根本上解决"物品没收容"问题**）
  - 解析 `[线索:]` → 增删 `s.clues`
  - 解析 `[地图:]` → 增删 `s.mapUnlock`
  - 解析 `[时间:]` → 调用 `advTime(Xh)`，触发死亡/事件/成就检查
  - 解析 `[死亡]` → 直接 `triggerDeathEnding()`
- **阶段 4 修复渲染**：
  - 把所有 `[xxx]` 机器标签从 `full` 正文中剥离（不显示给玩家看，只执行副作用）。
  - 选项块如果缺失 → 走原"补选项"逻辑（L850~ 附近 `topUpMsgs` 那段）。

### 4.3 `_buildFrameworkContext()` 在每次 hin() 调用时附加到 systemPromptExtra
- 在 Prompt 中用实际游戏数据的当前状态"实例化"几个协议标签示例，让 AI 更易理解：
  ```
  【本回合协议示例（不是要你输出）】
  当前：血量 {{hp}}/{{maxHp}} 饱腹={{hunger}} 口渴={{thirst}} 背包物品数={{invLen}}
  示例正确输出：
      （剧情段落…你撕开绷带用力绑住伤口…）
      [时间:+1h] [状态:血量-15 疲劳+20] [物品:-绷带x1 +医疗包x1]
      [choice]
      坐下来休息半小时
      继续搜索旁边的病房
      原路返回据点
      [/choice]
  ```

## 五、依赖与注意事项

1. **跨文件运行时解析**：gamesystems.js 中全部用箭头包装 `window.xxx`，新增函数（`_checkDeathNow`, `advTime`, `_validateAiOutput`）也必须在 main.js 定义后 `window.xxx = xxx` 暴露，gamesystems 端用 `const xxx = (...a) => window.xxx(...a)`。
2. **不要修改已有存档键**：旧存档的 `elapsedSec` 是秒数，但含义是"真实经过的自动流失秒"；新语义变为"玩家推进累计秒"，需要在 migrateSta 里做字段清零（如果玩家之前已经玩过一段时间 → 保持累计值不变，只是不再自动累加）。
3. **BGM 阻塞加载的兜底**：用户浏览器或 CDN 无法加载 mp3 时，必须 `setTimeout` 8s 后强制 `_bgmReady=true`，否则页面永远卡 loading。
4. **协议升级不破坏旧玩法**：`_validateAiOutput` 遇到旧版输出（不含任何 [xxx] 标签）时，不报错，按原有逻辑从叙事里正则提取物品即可——兼容老 AI 模型不遵守协议的情况。
5. **Token 优化不能影响剧情质量**：ctx 裁剪 + 摘要上线后，要观察 AI 是否会遗忘之前角色设定；遗忘时增加"历史关键信息保留条数"阈值。

## 六、风险与处理

| 风险 | 影响 | 处理 |
|------|------|------|
| advTime() 入口遗漏导致时间完全不推进 | 玩家属性永不衰减，无死亡 | 每个玩家输入后强制 `advTime(1h)` 默认值兜底；挂机 setTimeout 也走同一入口 |
| AI 不输出 [物品] 标签导致没收容 | 回归旧 bug | 保留原有"从叙事正则提取物品名"作兜底（修复 2 中的 hin() 扫描） |
| BGM 阻塞导致首屏白屏超时 | 用户直接退出 | 8s 硬超时 + 监听 `error` 事件立即 ready |
| 便签线索自动移除误删（匹配太宽） | 用户线索丢失 | 正则前先做 `s.clues` 精确/包含匹配再删；`undo` 栈支持 5 秒撤销 |
| 快速重开后成就虽重置但成就面板没重绘 | UI 误导 | 重绘 `_renderAchievements()` + 清 DOM 的 `.achievement-card.unlocked` 类 |
| 删除自动计时器后随机事件完全不触发 | 世界变得太平 | advTime 每小时按 eventFreq 抽一次；且战斗/搜索后概率保底抽一次 |
